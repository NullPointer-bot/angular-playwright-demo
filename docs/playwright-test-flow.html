Short answer first

Is this folder layout standard?

Partly. Playwright itself only needs spec files. Everything else here is a built-in Playwright feature (fixtures, network mocking) or a widely used pattern (page objects) that this project chose to organise into folders. The folder names are a convention, not a rule.

For a handful of tests, one spec file is fine. The layers start paying off when you have many tests touching the same screen: here, 19 tests × 3 browsers = 57 runs share one set of selectors and one fake backend.

    The link to the component

    How a line in the spec finds an element in the Angular template

    The connection is a string. The component puts data-testid="todo-input" on the element, the config tells Playwright that getByTestId() reads the data-testid attribute, and the page object asks for that id. Nothing imports Angular code.

    Spec writesPage object resolves toMatches in todo.component.ts
    todoPage.inputpage.getByTestId('todo-input')<input data-testid="todo-input" [(ngModel)]="newTitle">
    todoPage.addButtonpage.getByTestId('add-button')<button data-testid="add-button" type="submit">
    todoPage.itemspage.getByTestId('todo-item')<li data-testid="todo-item"> (one per todo)
    todoPage.itemAt(3).titleitems.nth(3).getByTestId('todo-title')<span data-testid="todo-title"> inside the 4th <li>
    todoPage.expectRemaining(3)getByTestId('remaining-count') has text "3 items left"<span data-testid="remaining-count">
    todoPage.headingpage.getByRole('heading', { name: 'Todos' })<h1>Todos</h1> (found by accessibility role, no test id)
    api.requestsOf('POST')not a locator: reads the mock's request listTodoService.create() → http.post('/api/todos', { title })

    If someone renames data-testid="todo-input", exactly one line in todo.page.ts changes, and all 19 tests keep working.
